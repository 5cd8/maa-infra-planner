# ADR 0001: 単一HTMLで作り、名前表を同梱する

- 状態: 採用
- 日付: 2026-10-31

## 背景

一图流の作成支援ツールは日本語に対応していない。日本版(グローバル版)MAAの基地スケジュールJSONを日本語で作る個人用ツールが必要。
入力は MAA が出力する OperBox JSON と、一图流が出す中国語版JSON。どちらも同じゲーム内IDを持つ。

## 決定

1. **単一HTMLファイルで配布・動作する。** サーバー・インストール・外部CDNに依存せず、ダブルクリックで開ける。データはブラウザ内だけで処理する。
2. **名前表を同梱する。** `resource/battle_data.json`(MAA本体)から、`id`・中国語名・日本語名・レア度を抜き出した表を生成し、HTMLに埋め込む。
3. **名前の変換はゲーム内IDを仲立ちにした名前表で行い、状態には日本語名の文字列だけを持つ。** 画面は日本語名、**出力は中国語名**（MAAは日本版でも中国語名で照合するため。実機確認済み）。変換は名前表で行い、日本語名↔中国語名は1対1。

## 理由

- 所持・昇進・レベルは OperBox から読めるが、`char_002_amiya` は OperBox に含まれない(別形態の `char_1037_amiya3` は含まれる。2026-10-31 時点の実データで確認)。名前表があれば、アーミヤの名前が OperBox に無いときに `char_002_amiya` = アーミヤを補える。
- 一图流以外の中国語JSON(`operators` 一覧なし)も、名前表の中国語名からIDを引けば変換できる。
- 名前表は MAA 更新時に再生成スクリプトで作り直せる。

## 採らなかった案

- C# WPF アプリ: MAA のフォルダを直接読み書きできるが、ビルドと配布の手間が増え、用途(入力補助+検証)に見合わない。
- Python CLI: 部屋とシフトの編集に向かない。
- OperBox と取り込み元JSONの `operators` 一覧だけで変換する(名前表なし): アーミヤのような例外を毎回手当てする必要があり、`operators` 一覧のないJSONを取り込めない。

## 影響

- 名前表の鮮度は、MAA本体の更新に追従して手動で保つ。
- 出力は中国語名のため、画面の日本語名とJSONの文字が一致しない。出力JSONを人が読むときは、取り込み側（本ツール）で日本語に戻して確認する。
- 配布物が大きくなる(名前表の分)。463件程度で、問題にならない見込み。
